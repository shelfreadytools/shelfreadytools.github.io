Shelf Ready Check

Point it at a skill, plugin or marketplace before you publish: front matter that does not parse, names, missing files, machine-only paths, undeclared packages, junk files and manifests. Free, MIT, Python 3.9 and nothing to install.

What it checks

  • Front matter: YAML that does not parse. An unclosed quote or a tab is enough for Claude Code to drop the front matter and describe the skill by its first heading; an unquoted : is read by Claude Code but stops YAML parsers, and so other agents and tools. Also missing front matter, unknown keys, and keys claude.ai and the API refuse.
  • Name and description: the Agent Skills rules (lowercase letters, digits and hyphens, at most 64 characters, the same as the folder; a description of at most 1,024 characters) and Claude Code's listing limit (1,536 characters).
  • Files the instructions point to: missing, or differing only in case (works on a Mac, fails on Linux).
  • Paths that only exist on your computer: /Users/<you>/..., /home/<you>/..., C:\Users\....
  • Python packages your scripts import that are neither in the standard library nor declared (requirements files, pyproject.toml, PEP 723 inline metadata).
  • Files that should not ship: .DS_Store, __pycache__, editor leftovers, environment and key files.
  • Plugins and marketplaces: plugin.json and marketplace.json fields, component paths, the icon, plugin sources that do not resolve; with Claude Code installed it also runs claude plugin validate --profile directory, which fails where Anthropic's plugin directory would refuse the plugin (why that flag matters).

It reads files only: it changes nothing, sends nothing, and does not run the skill.

Install

In Claude Code:

/plugin marketplace add shelfreadytools/shelf-ready-check
/plugin install shelf-ready-check@shelf-ready-check

Then ask Claude to check a skill or plugin before you publish it. Without Claude Code:

git clone https://github.com/shelfreadytools/shelf-ready-check
python3 shelf-ready-check/skills/check-skill/scripts/shelf_ready_check.py check path/to/my-skill

--json prints JSON, --out <folder> writes check.md and check.json, --fail-on medium sets the exit code for CI, and --target claude-ai adds claude.ai's stricter rules. Source: github.com/shelfreadytools/shelf-ready-check.

A real run

A small skill, csv-profile, with seven mistakes planted, installed with the plugin in a fresh Claude Code session (Claude Code 2.1.325, default model; no settings, skills or MCP servers of the author's). The prompt: "Check my skill in csv-profile before I publish it."

With python3 commands allowed, it ran the checker and answered (0.3 minutes, $0.11):

I ran the checker on csv-profile. It's not ready to publish yet: it found 3 high, 4 medium and 1 low finding.

SKILL.md:3: the front matter isn't valid YAML. An unquoted value contains : . Claude Code still reads it, but other agents' YAML parsers stop at that line, so the skill fails for them. Fix: put the value in quotes.

The other seven: a path under /Users/dana/, a link that differs from the file name in case, a .DS_Store, a __pycache__, the name differing from the folder, an undeclared chardet, and a version: key claude.ai refuses. The whole answer.

On first use nothing is approved yet, so Claude Code asks before it runs the script. In this run, where nobody could answer, the agent stopped and said so rather than guessing (0.2 minutes, $0.10; the run):

The checker hasn't run on csv-profile yet, because the command needs your approval. ... I won't read the files by hand and call that a check, because that misses things only the parser catches, such as front matter that doesn't parse.

That instruction is in the skill because an earlier build without it did read the files by hand, and reported "the front matter parses" for this very skill.

How well it works

Measured on held-out sets the rules were never tuned on: real open-source skills and plugins with mistakes planted by an independent agent, and every serious finding on the untouched originals judged by another. In the third round (version 0.1.2; the rules are unchanged since), it caught 48 of 65 planted mistakes (73.8%; 48 of the 56 of the kinds it looks for), and of the 7 medium or high findings it raised on 30 untouched items, the judge called 4 real. All three rounds, the weak ones included.

What else to run

  • claude plugin validate . --strict --profile directory: the manifests against Claude Code's schema, and the directory's own refusals (README, licence, system files).
  • claude plugin eval: your own test cases in an isolated session with only your plugin loaded.
  • Shelf Ready, the paid kit from the same author: one run of your skill in a fresh session installed the way a buyer gets it (permission prompts, failures, files written, cost), screenshot cards and a docs page from that run, a check of your listing copy against it, and a reproducible zip.
