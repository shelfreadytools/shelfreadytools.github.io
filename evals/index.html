How well the check works

Three held-out rounds: real open-source skills with planted mistakes, built and judged by independent agents.

Method

check was developed on two public skill collections (anthropics/skills and obra/superpowers) and on skills written for the tests. Published numbers come only from held-out sets that the rules were never tuned on:

  • An independent agent that never saw shelfready's code read the public docs (the Agent Skills specification, Anthropic's skill pages, Claude Code's skills and plugin docs), picked real open-source skills from repositories not used in development, copied them, and planted realistic mistakes of its own choosing in the copies, with a label for each (type, file, line). It also kept the untouched originals.
  • score_heldout.py (committed before the set was seen) checks each original and its planted copy the way shelfready check does. A mistake counts as caught when the planted copy has a finding the original lacks, in the labelled file, within two lines of the labelled line (or anywhere in a file labelled as a whole).
  • Every medium or high finding on the untouched originals went to a second independent agent, which judged it real or a false alarm from the skill's files and the docs (score_judged.py).
  • Each set is scored once. Changes made after a score are not re-measured on that set.

Missed (heldout-1/per_item.json): all three paths that assume an install folder (~/.claude/skills/<name>/); a key CSV and two junk files (.Rhistory, .cache/) the file lists lacked; a JavaScript syntax error and an undeclared npm package (JavaScript was not checked); a backslash path starting with a placeholder; a script path inside a reference file; two problems inside a plugin whose plugin.json was itself broken (its skills were not checked); a plugin path found but reported at the line of the skills key rather than the entry; a string author reported only as low.

False alarms (heldout-1/judged.jsonl): 7 "undeclared package" findings on scripts that declare their packages in inline metadata (# /// script, run with uv run); 6 backslash paths on lines written for Windows shells, where backslashes are right; 1 description that does say when to use the skill without the usual words.

All of these were fixed in 0.1.1 (see CHANGELOG). Those fixes are measured only by round 2.

Missed: commands that work only with GNU or only on macOS (3, not checked), documented flags a script does not accept (3, not checked), a jq dependency whose error the script hides, a JavaScript error that node --check itself passes, an install-folder path inside a reference file, a Windows path in a plugin's agent file; a near-identical file name in a table was reported only as low.

False alarms (heldout-2/judged.jsonl): 9 container paths (/home/node/.n8n in n8n's Docker image), 7 paths that are examples of the user's project, files the skill writes, or links to an upstream repository, 2 template files with {{placeholders}} read as Python, 1 package the docs show in an import example, 1 extra file in .claude-plugin/. Debatable: Claude Code keys (argument-hint) in skills written for Claude Code, reported for claude.ai.

0.1.2 changed what the severities mean (see CHANGELOG): high and medium are kept for near-certain rules, and context-dependent guesses are low notes. It is measured by round 3.

Also missed: a syntax error in a plugin's hook script and a hook path that ignores ${CLAUDE_PLUGIN_ROOT} (plugin hooks are not checked), a TypeScript syntax error, an undeclared npm package in a skill with a package.json, an editor backup (SKILL.md.bak), a Windows path, a description written below the closing ---; a skill file named SKILLS.md was reported ("no SKILL.md in this folder") but for the folder, not the file, so the rule fixed in advance does not credit it.
