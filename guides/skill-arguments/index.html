$ARGUMENTS, $0 and $1 in Claude Code skills: what each one becomes

Eight real runs on Claude Code 2.1.325: which placeholders a skill's arguments replace, which stay as literal text, and how a price like $5 in a skill turns into the sixth argument.

A skill sees its arguments through placeholders in SKILL.md. Most surprises come from three rules: indexes start at 0, a placeholder with no argument stays in the text as it is written, and any $ followed by a number counts as a placeholder, prices included.

Everything below comes from eight short sessions on Claude Code 2.1.325 (16 November 2026), each started with claude -p in a fresh project. The text shown is what Claude received: it is read from the session's own transcript, not from Claude's reply. The skills and the full transcripts are linked at the end.

The test skill

---
name: echo-args
description: Test skill that shows the text it received. Use only when asked to use echo-args.
---

Reply with only the word OK.

all: [$ARGUMENTS]
zero: [$0]
one: [$1]
two: [$2]
first again: [$ARGUMENTS[0]]
price: [it costs $5 a month]

Four things to take from it:

  1. Indexes start at 0. $0 is the first argument and $1 the second. $ARGUMENTS[N] is the same thing written out.
  2. A missing argument leaves the placeholder in the text. With no arguments, Claude was given the literal characters $0 and $1; with two, the literal $2. Only $ARGUMENTS becomes empty.
  3. A price is a placeholder. $5 waits for a sixth argument. With five or fewer it stays $5, so the skill looks fine every time you try it with one or two arguments, and then someone passes six and Claude reads "it costs f a month". Write \$5: Claude Code removes the backslash and shows $5, however many arguments there are.
  4. $ARGUMENTS keeps quotes; $0 and $1 do not. /echo-args "two words" third gave $0 = two words, $1 = third and $ARGUMENTS = "two words" third.

Four more cases

An argument that contains a placeholder is not expanded again. /echo-args $1 beta gave $0 = $1: the text the user typed, inserted as it is.

Named arguments become empty when missing. With arguments: [city, unit] in the front matter, /named-args Lisbon gave:

city: [Lisbon]
unit: []
all: [Lisbon]

So $unit and $1 behave differently: a missing named argument becomes empty, a missing $1 stays $1. Named arguments are the safer choice for optional values.

No placeholder at all: the arguments are added at the end. A skill with no placeholders, run as /no-placeholders alpha beta, was given its text followed by a new last line:

This skill has no placeholders.
ARGUMENTS: alpha beta

When Claude calls the skill itself, the same rules apply. Asked in plain words to use echo-args with the arguments alpha beta, Claude called the Skill tool with {"skill": "echo-args", "args": "alpha beta"}, and the text it received was the same as for /echo-args alpha beta.

These match Claude Code's skills documentation, which also covers argument-hint for autocomplete. Not tested here: skills that run with context: fork.

Writing a skill that takes arguments

  • Escape every $ that is followed by a digit in the skill's text: \$5, \$1.00.
  • Use named arguments (arguments: [file, format]) for anything optional, so a missing value is empty rather than a stray $1; or say in the skill what to do when no argument was given.
  • If the skill needs every word the user typed, use $ARGUMENTS; for separate values, tell users to quote values with spaces.
  • Try it with no arguments and with more than you expect, not only with the usual one or two.
