claude plugin validate passed. Will the plugin directory take it?

What claude plugin validate checks before you submit a Claude Code plugin to Anthropic's plugin directory, what it leaves out, and what to run instead. Real output from Claude Code 2.1.325.

Not necessarily. Plain claude plugin validate lists the problems Anthropic's plugin directory refuses a submission for, and then still says "Validation passed" and exits 0. With --profile directory it fails on them. Inside your skills, it reads the front matter the way Claude Code loads it, and nothing else: a path that exists only on your computer, a link that breaks on Linux or a package nobody declared all pass.

Everything below is real output from Claude Code 2.1.325 on 16 November 2026, on a small plugin built for this page. The full outputs are linked at the end.

The test plugin

A plugin, weather-notes, with one skill and eight problems planted:

  1. No README and no LICENSE.
  2. A .DS_Store at the top of the plugin.
  3. The skill's description has an unquoted : , which YAML parsers refuse.
  4. The skill's name (weather-note) differs from its folder (weather-notes).
  5. SKILL.md links references/Units.md; the file is references/units.md.
  6. The script imports requests, which nothing declares.
  7. An example path under /Users/sam/.
  8. A .zip inside the skill.

Numbers 1 and 2 block a submission, and number 8 is held for a reviewer, according to Anthropic's pre-submission checklist. The others do not stop a submission; they break the skill for some of the people who install it.

--strict gives the same result: exit code 0. A CI job that runs claude plugin validate . stays green on a plugin the directory will refuse. (The checklist itself still says that validate "doesn't check the directory's requirements, such as whether you have a README and license"; version 2.1.325 does list them, but only as notes.)

--profile directory fails, as the directory would

$ claude plugin validate <plugin> --strict --profile directory
...
✘ Validation failed (--profile directory: the plugin directory would refuse a
submission of this plugin)
[exit code 1]

This is the command for CI. validate reads the folder on disk, while a submission from a git repository holds only what is committed, so run it on a fresh clone: a .DS_Store that is on your disk but never committed is not submitted.

What validate reads inside a skill: the front matter

validate parses each skill's front matter the way Claude Code loads it. The same plugin with an unclosed quote in the description, instead of the colon, fails:

$ claude plugin validate <plugin>
...
Validating skill: <plugin>/skills/weather-notes/SKILL.md

✘ Found 1 error:

  ❯ frontmatter: YAML frontmatter failed to parse: YAML Parse error: Unexpected EOF.
    At runtime this skill loads with empty metadata (all frontmatter fields
    silently dropped).
...
✘ Validation failed
[exit code 1]

The unquoted colon passes, because Claude Code reads it too: in a session on the same version, Claude Code listed such a skill with its whole description (the test). A YAML parser stops on it ("mapping values are not allowed here"), so it matters when the skill is also meant for other agents or tools that read skills with a YAML parser.

What validate does not read

Problems 4 to 8 appear in none of the runs. Pointing validate at the skills folder does not find them either:

$ claude plugin validate <plugin>/skills
Validating components in: <plugin>/skills

✔ Validation passed
[exit code 0]

Pointed at the skill's own folder, it stops with "No manifest found in directory".

Nothing on this page flagged the archive. Before you submit, look for binary files yourself: the checklist holds any file that is not text, an image or a font (an .ico, .pdf or .zip), and any file over 256 KiB that is not an image or font, for a reviewer.

Before you submit

  1. claude plugin validate . --strict --profile directory on a fresh clone of the repository.
  2. A check of what is inside the skills: Shelf Ready Check (/plugin marketplace add shelfreadytools/shelf-ready-check), or read each SKILL.md yourself for paths, links and packages.
  3. If you have eval cases, claude plugin eval runs them in an isolated session with only your plugin loaded.
  4. No archives, PDFs or other binary files, and the icon you want: validate's own note says the first icon saved in the developer portal becomes the listing icon, and changing it later does not change the listing.
